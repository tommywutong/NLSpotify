# NLSpotify 项目深度梳理

> 这份文档是项目的代码事实和后续接手入口。面试表达可以参考 `面试技术亮点与优化点.md`，但以本文和当前源码为准，不把规划或自测结果当成已验证能力。

## 1. 项目定位

NLSpotify 是一款仿 Spotify 风格的 iOS 音乐流媒体 App，使用 Objective-C/UIKit 开发，通过网易云音乐 API 代理获取音乐内容。项目包含推荐首页、歌单/专辑浏览、在线播放、歌词、评论、下载、播放历史、喜欢歌曲、本地歌单和音乐库等功能。

项目最有代表性的三条技术主线：

1. `AVAssetResourceLoader` 驱动的音频 Range 缓存。
2. 播放器切歌场景的递增 Token 异步一致性控制。
3. 网络层对 401/301 登录失效的刷新队列和统一重试。

## 2. 架构和数据流

```text
UIKit View / ViewController
        ↓
MVC + 局部 ViewModel
        ↓
Service API 层
        ↓
NetWorkManager + NLAuthManager
        ↓
Repository 数据访问层
        ↓
WCDB + 音频文件缓存
```

- **App 层**：`AppDelegate` 初始化数据库和缓存；`SceneDelegate` 根据登录状态显示登录页或 TabBar，并处理强制登出。
- **UI 层**：纯代码 UIKit + Masonry，没有依赖 Storyboard；首页使用 `NLHomeViewModel` 组织分区数据。
- **Service 层**：每类 API 独立封装，例如歌曲播放 URL、歌词、歌单、专辑、评论、推荐和搜索建议。
- **网络层**：`NetWorkManager` 统一注入 Cookie、处理 HTTP/业务错误和认证恢复。
- **Repository 层**：封装 WCDB CRUD，避免页面直接拼接数据库操作。
- **播放层**：`NLPlayerManager` 是全局播放器单例，通过 ReactiveObjC 信号向小播放器、全屏播放器和 TabBar accessory 分发状态。
- **缓存层**：`NLCacheManager` 用稳定 `songId`（缺失时回退 URL）散列定位文件与 WCDB 记录；8 条串行队列按文件标识分片，保证同一文件顺序写入。

## 3. 核心用户流程

1. 启动时创建 WCDB；`NLCacheManager` 在 Utility 队列异步创建缓存表并核对缓存目录与账本。读写、LRU、播放器、下载和缓存列表通过 ready gate 异步准入，启动路径不等待目录扫描。
2. 游客登录成功后保存 Cookie 和登录状态，进入主 TabBar。
3. 首页用 `dispatch_group` 并发加载五个推荐分区。
4. 用户选曲时先检查已完成的 `songId` 缓存；命中则用本地文件播放，否则用已有播放 URL 或请求新 URL 创建 `AVPlayerItem`。
5. 播放 URL 被替换为 `streaming://`，AVPlayer 的请求交给 `NLResourceLoader`。
6. 小播放器和全屏播放器订阅状态信号；歌词页根据播放进度更新当前行。
7. 播放历史、喜欢歌曲、下载记录、本地歌单和歌单歌曲关系写入 WCDB。

## 4. 亮点一：L1/L2/L3 音频缓存与 Range 回源

关键文件：

- `NLSpotify/Modules/播放器/缓存/NLAudioMemoryCache.m`
- `NLSpotify/Modules/播放器/缓存/NLResourceLoader.m`
- `NLSpotify/Modules/播放器/缓存/NLCacheManager.mm`
- `NLSpotify/Modules/播放器/NLPlayerManager.m`

### 实际实现

```text
L1：NSCache 音频热点 segment
  → L2：未完成 .tmp + WCDB Range 账本
  → L3：完整 .mp3
  → Origin：HTTP Range 回源剩余请求区间
```

1. 播放器把真实 HTTP URL 的 scheme 替换成 `streaming`，由 `AVAssetResourceLoaderDelegate` 接收请求。
2. `NLAudioMemoryCache` 先按 URL + offset 返回连续内存 segment；部分命中后继续查下层。
3. L2 命中时，依据 WCDB 的 `cachedRangesString` 从 `.tmp` 用 `pread` 读取连续字节并回填 L1。
4. L3 是完整 `.mp3`：Loader 可按 Range 读取；`NLPlayerManager` 也可直接用 file URL 创建本地 `AVPlayerItem`。
5. L1/L2/L3 不能完整满足时，Loader 只为当前连续缺口创建有界 HTTP Range；网络数据同时响应 AVPlayer、回填 L1 与 L2 `.tmp`，完成当前缺口后重新检查后续内存/磁盘区间，避免跨已缓存区间重复下载。
6. 当前任务产生的区间与数据库区间合并；只有 `[0, totalLength)` 无空洞覆盖，才在同 MD5 队列用原子 `rename` 将 `.tmp` 晋级为 `.mp3`，不保留重复正文。
7. 显式下载若已有同 `songId` 的完整缓存，直接建立下载记录，不重新取播放 URL 或重复写入正文。

### 并发和清理

- 文件名和 `NLAudioCacheInfo` 主键优先使用 `songId` 的 MD5；无稳定 ID 才回退 URL 的 MD5。
- 8 条串行 GCD 队列按标识分片；同一文件顺序写入，不同标识落在同一队列时也会串行。
- 已缓存区间以 JSON 字符串存储，内存中转换为 `NSRange` 数组并合并重叠或相邻区间。
- L1 由 `NSCache` 的 12 MiB / 512 段限制与内存警告独立淘汰。
- L2 的 `cleanPartialCacheWithMaxSize:` 按 `.tmp` 文件大小执行 128 MiB LRU；L3 的 `cleanCompletedCacheWithMaxSize:` 按 `.mp3` 文件大小执行 500 MiB LRU。当前播放标识、活动下载与已完成离线下载受保护，删除成功后同步删除 WCDB 记录。
- 对账完成前，缓存相关请求登记为 pending；完成后总是异步投递到调用方指定队列。ResourceLoader 取消、切歌 token、下载 generation 和缓存列表刷新 token 会丢弃 ready 前已失效的请求。
- 启动对账遇到 `.tmp` 不存在、`.mp3` 存在的未完成记录时，仅在持久化 Range 账本完整覆盖 `[0,totalLength)` 且文件大小精确匹配时恢复 `isFinished`；WCDB 修复失败会保留文件供下次重试，但本次仍是缓存未命中。缓存歌曲列表的 Repository/WCDB/文件筛选和最近访问时间读取在 Utility 队列完成，每首命中歌曲只取一次最近访问时间，排序只读内存快照；UI 结果回主线程后用 reload token、模式和窗口层级检查丢弃过期结果。
- 清空缓存先递增 generation 使旧写入失效，异步等待已登记缓存操作完成后删除 L1/文件/账本，再放行清空期间登记的新写入；不使用 semaphore 或 `dispatch_group_wait` 阻塞启动或网络 delegate 队列。

### 面试时的准确表述

可以说“减少一次高层内存拷贝”，不要绝对称为真正零拷贝；`pread` 仍要把数据读到用户态 buffer。完整 `.mp3` 能按 `songId` 在没有播放 URL 时直接创建本地 `AVPlayerItem`；真实音频可播放性、首帧时延与网络命中率仍需真机验证。启动对账恢复只保护完整 Range 账本且长度匹配的 rename 窗口；不校验内容摘要，因此同长度内容损坏无法识别。文件 rename 与 WCDB 更新不是跨系统事务，数据库修复失败的候选只保留待重试，不作为完成缓存命中。

## 5. 亮点二：切歌 Token

关键文件：`NLSpotify/Modules/播放器/NLPlayerManager.m` 的 `playSongAtIndexIfNeeded:` 与 `playWithURL:`。

`playSwitchToken` 是单调递增版本号：

```objc
NSUInteger token = ++self.playSwitchToken;

if (token != self.playSwitchToken) {
    return;
}
```

切歌、停止与新播放器资源建立会递增 Token。播放 URL 和进度回调在回主线程后确认 Token 与当前 `AVPlayerItem`；暂停意图在资源就绪前也保持不变。

切歌时旧流式 Loader 被取消，已完成的文件写入仍可合并 Range；歌词加载用 `currentLyricSongId` 拦截旧歌词。Token 不能替代网络取消和音频文件一致性校验。

## 6. 亮点三：301/401 刷新队列

关键文件：

- `NLSpotify/Networking/网易云API/NetWorkManager.m`
- `NLSpotify/Networking/网易云API/Login && 双Token/NLAuthManager.m`
- `NLSpotify/App/SceneDelegate.m`

网络层同时识别 HTTP 401 和网易云业务码 301。第一个失效请求在串行 `refreshLockQueue` 中成为刷新请求，其余请求进入 `pendingRequests`。刷新成功后统一重试一次；失败则统一回调失败、清理登录状态并发送 `NLForceLogoutNotification`，由 `SceneDelegate` 切回登录页。

这是 Cookie/Refresh 机制，不是 OAuth2 Bearer Token。当前 Cookie 保存在 `NSUserDefaults`，后续可迁移到 Keychain。

## 7. 播放器和响应式状态

`NLPlayerManager` 对外提供：

- `playbackStateSignal`
- `songSignal`
- `progressSignal`
- `cacheProgressSignal`
- `hasPlaylistSignal`

播放器还实现了：

- 列表循环、单曲循环、随机播放。
- 下一首 `AVPlayerItem` 预创建和命中切换。
- `AVAudioSession` 后台播放配置。
- `MPRemoteCommandCenter` 播放、暂停、上一首、下一首和拖动进度。
- `MPNowPlayingInfoCenter` 锁屏标题、艺术家和封面信息。

进度观察器在串行时间队列中发送信号，页面收到后切回主线程更新 UIKit。

## 8. 歌词和评论

### 歌词

`NLMusicPlayerViewController` 使用正则解析 LRC 时间标签，兼容两位/三位毫秒，并对多时间标签行展开后排序。正常播放时从当前行继续线性搜索，快退时从头搜索；切歌时用歌曲 ID 丢弃旧歌词回调。

当前短板：没有二分查找，当前行变化时使用整张歌词表 `reloadData`，没有逐字高亮。

### 评论

`NLCommentTextFolder` 使用 TextKit 的 `NSTextStorage`、`NSLayoutManager`、`NSTextContainer` 计算行数。超过三行时生成折叠文本，折叠态/展开态的富文本和高度保存在 `NLCommentModel`，展开后通过 `beginUpdates/endUpdates` 触发高度重算。

当前短板：缓存挂在 Model 上，没有全局 `NSCache` 的淘汰策略；评论富文本还没有链接、@mention 等交互。

## 9. WCDB 本地数据

数据库路径为 Documents 下的 `NLSpotify_v2.sqlite`。主要表和 Repository：

| 数据 | Repository / 模型 |
| --- | --- |
| 播放历史、喜欢歌曲、下载歌曲 | `NLSongRepository` / `NLSong` |
| 本地歌单和歌单歌曲关系 | `NLPlayListRepository` / `NLPlayListSongRelation` |
| 收藏专辑 | `NLAlbumRepository` / `NLAlbum` |
| 下载队列 | `NLDownloadRepository` / `NLDownloadItem` |
| 搜索历史 | `NLSearchRepository` / `NLSearchRecord` |
| 音频缓存账本 | `NLCacheManager` / `NLAudioCacheInfo` |

新增模型应继续遵循 `.h + .mm + +WCDB.h` 三文件约定。当前数据库写入没有统一事务和独立写队列，属于后续改进点。

## 10. 已实现和未完成边界

### 已实现

- 首页推荐和多分区并发加载。
- 歌单/专辑详情、歌曲列表、播放全部、随机播放。
- 流式播放、Range 缓存、缓存进度和 LRU 清理。
- 小播放器、全屏播放器、播放队列、歌词同步。
- 评论分页、动态高度、文本折叠/展开。
- 播放历史、喜欢歌曲、收藏专辑、收藏歌单和本地歌单。
- 下载队列和下载完成后的本地歌曲记录。
- 游客登录、Cookie 刷新和强制登出跳转。

### 当前未完成或需要谨慎描述

- 搜索结果页目前只打印搜索文本，没有真正展示歌曲搜索结果，也没有防抖和请求竞态保护。
- 广播页和独立创建页基本是占位页面；本地歌单创建功能在音乐库内已实现。
- 显式下载使用普通 `NSURLSession`，从 `bytes=0-` 开始，不是完整的后台断点续传。
- 登录页面目前实际支持游客登录，其他登录按钮是占位。
- 播放历史以歌曲 ID 为主键，重复播放同一歌曲会覆盖旧记录。
- 缓存 XCTest 覆盖稳定身份、Range 校验、L1/L2/L3 读写、ready gate、清空 generation、rename 后账本恢复/不完整账本/错长文件/WCDB 修复失败、缓存列表后台查询与过期结果丢弃、ready 前 Loader 取消与取消后 pending 清理、停止时丢弃待执行播放以及取消待执行下载；真实音频/CDN 行为仍需设备验证，跨启动取消/DB 落库竞态还需补测。
- README/Podfile 以 iOS 13 为设计目标，但当前 Xcode 工程配置中存在 `IPHONEOS_DEPLOYMENT_TARGET = 26.1`，发布前需要统一。

## 11. 后续优先级

1. 缓存启动对账现可恢复持久化完整 Range 账本对应的 rename 崩溃窗口；仍无法发现同长度内容损坏，也不能把文件系统 rename 与 WCDB 更新变成跨系统事务。
2. 缓存区间合并、歌单写入和下载状态更新增加 WCDB 事务。
3. 所有数据库写操作移到专属串行队列，避免播放回调直接做 I/O。
4. 搜索增加 300ms 防抖和 Token 竞态保护，并补齐结果 UI。
5. 下载改为后台 `URLSessionConfiguration`，设计真正的持久化断点续传。
6. 将 Cookie 迁移到 Keychain，补充 Range 合并、认证队列和 Repository 单元测试。
